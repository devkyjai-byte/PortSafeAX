## 오프라인 시연 패키지

개발 환경에서 `python -m scripts.package_demo`를 실행하면 `deliverables/PortSafeAX_offline_demo.zip`이 생성됩니다. 전체 압축을 푼 뒤 `index.html`을 여세요. 두 시연 HTML·합성 JSON·열람 안내와 파일별 SHA-256 목록을 포함합니다. 실행 앱·관리자 검토 기록·기획서·공모전 원본은 포함하지 않습니다. ZIP은 Git에 올리지 않으며 생성 도구와 검사를 관리합니다.

무결성 확인: `python -m scripts.package_demo --verify deliverables/PortSafeAX_offline_demo.zip`. 해시는 손상·차이 확인용으로 제작자 인증이나 현장 검증을 뜻하지 않습니다. 필수 제출서류 묶음도 아닙니다.

## GitHub 자동 검증

GitHub Actions의 `Validate MVP`는 main 업로드·PR·수동 실행 시 Windows와 Ubuntu의 Python 3.12에서 고정 의존성 설치, 의존성 충돌 검사, 전체 테스트, 합성 시연 재생성 및 저장된 결과와의 일치 검사를 수행합니다. 코드 변경으로 시연 결과가 달라지면 시연 파일도 재생성해 함께 커밋해야 합니다. 실행 결과는 [Actions](https://github.com/devkyjai-byte/PortSafeAX/actions/workflows/validate.yml)에서 확인하세요. 이는 소프트웨어 검사이며 현장 안전성이나 센서 성능 검증은 아닙니다.

설정 방식 참고: [GitHub 공식 Python 자동 검사 안내](https://docs.github.com/en/actions/tutorials/build-and-test-code/python).

## 로컬 실행

Windows와 Python 3.11 이상이 필요합니다(Python 3.12에서 검증). **`run_demo.bat`을 더블클릭**하면 독립 `.venv` 생성, 의존성 설치, 로컬 대시보드 실행을 수행합니다. 첫 실행에는 인터넷이 필요하며, 설치 후에는 오프라인 실행할 수 있습니다. 브라우저가 자동으로 열리지 않으면 http://127.0.0.1:8501 에 접속하세요. 종료는 실행 창에서 Ctrl+C입니다.

수동 실행:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

테스트 및 합성 데이터 파일 생성:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m portsafe.synthetic --seed 42 --scenario standard --output data/synthetic_demo.json
```

대시보드는 생성기를 직접 호출합니다. `data/synthetic_demo.json`은 재현 가능한 예시 파일이며 앱의 업로드 입력 기능은 아닙니다. `requirements.txt`는 직접 의존성 버전을 고정합니다. 전체 설치 버전은 `requirements-lock.txt`에 기록합니다.

## 계산 및 배정 가정

관리자 검토 기록은 실행 앱의 전용 탭에서 사용합니다. 작업별 검토 확인·보류·입력 정정 요청과 사유를 추가하고 해당 계획과 함께 JSON으로 다운로드할 수 있습니다. 미배정 작업의 검토 확인은 거절하며, 모든 기록은 배정을 변경하지 않는 메모입니다. 입력·계획별 이력을 분리합니다. 현재 연결 세션에만 보관되어 새로고침이나 연결 종료 시 사라질 수 있습니다. 저장한 JSON은 같은 시나리오·시드·계획을 선택한 뒤 ‘저장한 검토 기록 불러오기’에서 복원합니다. 최대2MB·1,000건이며 중복은 추가하지 않고 기존 이력과 충돌하면 거절합니다. 다른 버전에서 계획 내용이 바뀐 파일은 불러올 수 없습니다. 인증·서버 영구 저장·변조 방지·현장 승인 기능은 없으며 정적 HTML에는 이 기능이 없습니다. 형식과 계획 일치 검사는 작성자의 진위를 증명하지 않습니다.

- 작업부담 점수 = 0.35 × 중량지수 + 0.25 × 반복지수 + 0.25 × 자세지수 + 0.15 × 열환경지수. 입력·출력 0~100. 입력은 kg 또는 섭씨가 아닙니다.
- 추가 부담 = 점수 × 작업시간(시간). 추가 피로 = 추가 부담 × 0.12. 초기 상태에 누적합니다. 근무시간·피로·부담 상한과 정확히 같은 값은 허용합니다.
- 기본 상한 8시간, 피로 80, 부담 300은 **시연 가정**이며 법정 기준 또는 의학적 안전 기준이 아닙니다.
- 우선순위(3이 먼저), 높은 점수, 작업 ID 순으로 처리합니다. 가능한 작업자 중 배정 후 세 상한 대비 최대 사용 비율이 가장 낮은 사람을 선택하고 동률이면 작업자 ID 순입니다.
- 탐욕적 휴리스틱이며 전역 최적·최대 배정량을 보장하지 않습니다. 후순위 작업이 미배정될 수 있습니다.
- 작업자는 한 계획 구간에서 순차 수행한다고 가정합니다. 시간창, 교대, 휴식 회복, 동시 작업, 이동, 장비, 팀 작업은 미구현입니다.
- 초기 상태부터 상한을 넘는 작업자에게 추가 배정을 하지 않습니다. 초기 위험 자체를 해결하는 알고리즘은 아닙니다.
- 기준안은 첫 두 작업자에게 번갈아 배정한 의도적 불균형 예시이며 현실의 운영 수준을 대표하지 않습니다. 미배정 때문에 피로가 줄 수 있으므로 감소율이나 실제 효과를 주장하지 않습니다.

## Phase 1 설계 및 후속 검증

`docs/PHASE1.md`에 데이터 계약·안전 불변조건·수용 기준을 기록했습니다. `docs/DEMO_GUIDE.md`는 발표 순서와 제출 점검용입니다. 단위 테스트는 각 제약, 경계값, 중복·비정상 입력, 재현성 및 300개 합성 조합을 확인하고 Streamlit AppTest는 화면의 세 시나리오와 시드 변경을 실행합니다. 이는 소프트웨어 동작 검증이며 현장 안전성 검증이 아닙니다.

현장 적용 전 산업안전 전문가와 점수·상한을 검토하고 실제 데이터 동의·비식별화·보관 정책을 수립해야 합니다. ML 단계에서는 시간/작업자 분리 검증과 외부 검증, 편향 점검을 별도로 수행합니다. SafeBack 모듈은 장치 규격·보정·결측·시계 동기화·동의 절차 확정 후 연결합니다. 이 MVP는 실제 현장 배치 명령을 전송하지 않습니다.
